Where a recording goes

Each stage has a different job. Receiving a file does not mean it is ready for training. Open a stage to see what it produces.

  1. RecordMCAP files on the robot
  2. UploadSend selected stable files
  3. Verify & storeCheck bytes and register sources
  4. ProcessParquet; Pro adds episodes and QA
  5. Query & reviewExplore data; Pro adds review
  6. Cut & exportSigned training datasets, Pro only

PostgreSQL stores metadata and work records. The object store (RustFS) stores source and derived files. Core supports upload, integrity checks, Parquet, query, and the UI. Pro adds episodes, media, quality checks, dataset cuts, and export.

Record: keep the source files on the robot

The recording system produces MCAP files. Robot-side storage builds manifests that describe the files and their hashes. It waits for files to stop changing before preparing them.

Retention controls protect pending, failed, and active uploads by default. Read the storage guide before changing deletion rules.

Robot storage guide
Upload: send selected files when a connection is available

An operator starts an upload through the CLI or robot console. The agent queues files and retries temporary failures. Version-one resume sends only the missing parts. The agent always requests it, and the ingest server must support it.

A release deployment uses server-authenticated TLS and a per-robot bearer credential (the default token profile). The optional mtls profile also requires a robot certificate. Follow the guide for your deployment.

Upload and enrollment guide
Verify & store: confirm the received file matches the source

Ingest checks the assembled file against its expected SHA-256 hash before reporting completion. PostgreSQL records the upload and its identity. The object store holds the file bytes.

A hash confirms that the bytes match. It does not prove that the robot data is accurate or suitable for training.

Ingest integrity and storage reference
Process: create queryable data and quality results

The processor reads MCAP and writes registered Parquet files. In Pro, it also creates episodes, media, and quality results. The quality checks are documented with the Pro edition.

DEFECT measures data quality. RISK measures operational risk in the recorded scene. Both scores run from 0 to 100; higher is better. They are separate scores; do not combine them into one judgment.

Processing reference
Query & review: inspect what the system registered

The query service and Orbit UI expose registered data. Use Overview, Intake, and Explore to inspect the system and recordings. Review and Verification are Pro-only routes.

A useful query result is not yet a signed export. Continue with a reviewed dataset selection when preparing training data.

Product walkthrough · Query console guide
Cut & export: select a dataset and verify its source records

In Pro, a dataset cut records a selected set of episodes. Export produces a LeRobot v3 bundle or eligible, reviewed MCAP passthrough data. The signed records support source tracking and offline verification.

A signature confirms the signed records. It does not guarantee that a dataset is safe or suitable for every training task.

Terms you will see

MCAP
A recording file format for timestamped messages from a robot.
Parquet
A column-based file format. Robot Vault uses it to query extracted recording data.
Episode
A selected time range within a recording, used for review and dataset selection.
Manifest
A record of files and their identities, such as sizes and hashes. Its fields depend on the workflow.
SHA-256
A hash function used to compare file content and detect changed bytes.
TLS and mTLS
TLS protects a connection and authenticates the server. Mutual TLS also authenticates the client with a certificate.
QA
Quality assurance. The checks report data defects and operational risks separately.
Dataset cut
A recorded dataset selection. Export creates the files for training from that selection.
